# Context policy

## Regla base

Leer el menor contexto suficiente para decidir o actuar.

## Orden recomendado

1. Pedido del usuario.
2. Índice de épicas si hay que clasificar una idea nueva.
3. Epic card y task card activa, si existen.
4. Documentos de proyecto directamente relacionados.
5. Fragmentos puntuales de modelos, seguridad, vistas o tests.
6. Historial amplio solo si el usuario lo pide o es estrictamente necesario.

## Evitar

- leer todo el repo por defecto;
- crear un backlog plano acumulativo tipo `todo.md`;
- inferir reglas de negocio no documentadas;
- mezclar decisiones antiguas con criterios actuales sin validar.
